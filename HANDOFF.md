# Remixer macOS handoff

## Mission

Port the working Remixer 0.1.1 Windows desktop application to macOS, preserving the existing workflow and UI:

1. Import an authorized YouTube URL or a local audio file.
2. Display a seekable waveform with working playback, looping, and draggable time selection.
3. Detect track BPM and key, including selectable half/double-time and key-mode alternatives.
4. Detect the chord progression inside the selected waveform region.
5. Run local AI stem separation in either six-stem or HQ-vocal mode.
6. Preview stems and render full-length or selection-only 32-bit float WAV files.
7. Copy one or more resulting files to the macOS clipboard in a Finder-compatible form for an Ableton Live workflow.

This ZIP is a source handoff, not a runnable Mac build. Start by reading this file, `README.md`, `package.json`, and the files named in the porting matrix below. Do not copy the PowerShell/CUDA assumptions into the Mac implementation.

## Source baseline

- App version: `0.1.1`
- UI: Electron + React + TypeScript + Vite + WaveSurfer.js
- Engine: persistent Python 3.11 JSON-lines worker
- Audio: yt-dlp, FFmpeg/ffprobe, librosa, soundfile
- Separation: `bs-roformer-infer` pinned to commit `b0f1386fcced25f559f3e61c9f08a73cd9bddf80`
- Six-stem model: `roformer-model-bs-roformer-sw-by-jarredou`
- HQ-vocal model: `roformer-model-bs-roformer-leap-xe-vocals-by-pcunwa`
- Source control note: the Windows source directory was not a Git repository when this handoff was made. Initialize a repository on the Mac before editing so the port has a clean baseline.

The archive intentionally excludes Windows installers, compiled renderer/Electron output, `node_modules`, Python environments and caches, pytest scratch data, model weights, and the user's downloaded tracks. Recreate all generated dependencies locally.

## Verified Windows behavior

The following was implemented and exercised on the source machine:

- Local-file import and yt-dlp acquisition.
- Compact waveform peaks generated by the Python worker.
- HTTP-style byte-range serving through the `remixer-media` Electron protocol, so long lossless audio can seek and play without decoding the whole file in Chromium memory.
- WaveSurfer playback, seek, looping, new-selection drag mode, and selection adjustment/resize mode.
- BPM analysis with half/double-time alternatives.
- Passage-voted key analysis with Camelot code and mode alternatives.
- Beat-synchronized chord analysis over the selected region.
- Full and selected-region 32-bit float WAV rendering.
- Six-stem BS-RoFormer separation and Leap XE vocal separation.
- A Leap XE shape mismatch was fixed by aligning the session chunk size to the model STFT hop (`881559 -> 881152`). Keep `_align_session_chunk_size()` in `worker/remixer_worker/separation.py`.
- Windows Explorer file clipboard support through native `CF_HDROP` data.

Final validation on Windows passed:

- TypeScript typecheck.
- Five renderer tests.
- Six Python tests.
- A real Leap XE CUDA smoke test: source, vocals, and instrumental outputs each contained exactly 352,800 frames.

One real track was estimated at 147.66/73.83 BPM and G major after the analysis improvements. Automatic key/chord estimates remain probabilistic; retain the existing alternative-selection UX.

## Porting matrix

| Area | Current Windows implementation | macOS work |
|---|---|---|
| App data | `src/electron/main/main.ts` combines `LOCALAPPDATA` and `Remixer` | Use `app.getPath('userData')` directly, or a single well-defined child path. Avoid producing `.../Remixer/Remixer`. Expected user data location is under `~/Library/Application Support/Remixer`. |
| Python lookup | `src/electron/worker-client.ts` only searches `.venv\\Scripts\\python.exe` | Search `.venv/bin/python` on Darwin. Keep `REMIXER_PYTHON` as the highest-priority override. |
| Engine installer | `scripts/setup-engine.ps1`; Electron launches `powershell.exe` | Add a macOS setup script and dispatch by `process.platform`. Use an arm64-native Python 3.11 environment on Apple Silicon. Do not install the CUDA wheel index. |
| FFmpeg | Expected on `PATH` | Use Homebrew (`brew install ffmpeg`) for development. For a self-contained release, either bundle redistributable binaries with notices or make the prerequisite and error UX explicit. Validate paths from a packaged GUI, whose `PATH` is often smaller than an interactive shell's. |
| Compute status | `worker/remixer_worker/health.py` reports only CUDA | Report Apple MPS/MLX availability as applicable, plus the actual separation backend/device. Keep CPU fallback visible. |
| Model loading | `worker/remixer_worker/separation.py` requests Torch CUDA, then Torch CPU | Select the best validated Mac backend. Investigate the pinned library's MLX backend first on Apple Silicon, but test both named models because backend/model support may differ. Otherwise try a supported Torch MPS path, then CPU. Never claim MPS/MLX merely because it imports: run exact-length inference tests. Make progress copy device-neutral (not “on the GPU”). |
| Clipboard | `src/electron/clipboard.ts` writes Windows `CF_HDROP` | Implement a Darwin path that publishes file URLs/paths on `NSPasteboard` in a form Finder accepts. A tiny Swift/Objective-C helper is acceptable. Validate multiple files, spaces/Unicode, paste into Finder, and the intended Ableton Live view. Plain text paths are not sufficient. Retain the Windows implementation behind a platform dispatch. |
| Packaging | `package.json` and `scripts/package.mjs` are NSIS/Windows-only | Add `mac` targets (start with Apple Silicon `dmg` plus `zip`; add universal only after native dependencies are proven). Include the worker and the Mac setup helper in `extraResources`. Make `scripts/package.mjs` choose the host target or create separate scripts. |
| Signing | None for local Windows build | A local unsigned build is fine for development. For distribution, add Developer ID signing, hardened runtime entitlements, notarization, and stapling. Do not invent credentials. Document any local Gatekeeper workaround only for the owner's own unsigned build. |
| Window behavior | Already keeps the app alive when all windows close on Darwin | Verify dock activation, app menu/keyboard shortcuts, close/reopen, and quit behavior. |
| Paths/processes | Most Python code uses `pathlib`; subprocess flags are already conditional | Exercise spaces, Unicode, long paths, symlinks, hard-link fallback, and packaged resource paths on an actual Mac. |

## Recommended implementation order

1. Initialize Git and commit the received source as the untouched baseline.
2. Install arm64 Node.js and Python 3.11. Run the renderer and Python unit tests before changing code.
3. Make app-data, Python discovery, FFmpeg discovery, and engine setup platform-aware.
4. Launch the development app and validate import, waveform peaks, playback, seek, looping, selection creation, and selection adjustment before working on AI models.
5. Port health/device reporting and separation backend selection. Run a short real inference with each model and verify input/output sample counts exactly.
6. Implement macOS file clipboard support and test it with Finder first, then Ableton Live. Keep “Show in Finder” as a reliable fallback.
7. Add Apple Silicon packaging. Inspect the unpacked app resources and test the installed build, not only `npm run dev`.
8. Only after the arm64 build is stable, decide whether universal packaging and signing/notarization are needed.

## Suggested local setup

Adapt these commands to the Mac's package manager and architecture; they are a starting point, not a blind install script:

```bash
brew install ffmpeg uv
npm ci
uv python install 3.11
uv venv --python 3.11 .venv
uv pip install --python .venv/bin/python -r worker/requirements-core.txt
uv pip install --python .venv/bin/python -r worker/requirements-engine.txt
uv pip install --python .venv/bin/python -r worker/requirements-dev.txt
export REMIXER_PYTHON="$PWD/.venv/bin/python"
npm run typecheck
npm test
PYTHONPATH="$PWD/worker" .venv/bin/python -m pytest worker/tests -q
npm run dev
```

Confirm what PyTorch build the pinned engine dependency resolves on the target Mac. If adding MLX or changing PyTorch, pin the resulting versions rather than leaving the production engine dependent on whatever is newest.

## Acceptance checklist

The Mac port is complete only when all of these pass on the actual target Mac:

- `npm ci`, typecheck, renderer tests, Python tests, production build, and package complete cleanly.
- The installed app launches from Finder without needing a Terminal environment.
- Engine installation gives useful progress/errors and survives paths containing spaces.
- A local MP3/M4A/WAV imports and becomes a 44.1 kHz stereo float working WAV.
- An authorized YouTube URL downloads its highest-quality available audio stream and imports successfully.
- The waveform appears promptly, transport buttons work, clicking seeks, loop works, and both selection modes work.
- Track BPM/key and selected-region chords return results; all alternative controls remain usable.
- Both named separation modes finish on a short real track without shape errors or output drift.
- Every produced stem has the same sample count/alignment, and stems are not independently normalized.
- Full and selection clips are valid 32-bit float WAV files.
- Copying one file and multiple files pastes into Finder; filenames with spaces and Unicode work.
- Copied results can be brought into Ableton Live. If direct paste depends on Live's focused view/version, document the exact tested behavior and keep Finder/show-in-folder fallback obvious.
- Model downloads are cached under the app's Mac data directory and are not bundled into routine UI releases.
- An offline/relaunch pass works for already-downloaded tracks/models.

## Important implementation notes

- Preserve Electron context isolation and the narrow preload IPC API.
- Preserve custom byte-range media serving in `src/electron/main/main.ts`; it fixed broken controls and seeking on large WAV files.
- Preserve compact waveform peaks and do not send full decoded track arrays over IPC.
- Keep the Python worker persistent. Model/session caching is important because reloads are expensive.
- Keep the STFT-hop chunk alignment fix and exact output-length tests.
- Do not normalize individual stems or introduce timing-changing sample-rate conversions after separation.
- The checked-in `package-lock.json` is the JavaScript dependency source of truth. Avoid unrelated dependency upgrades during the port.
- Model weights are runtime downloads with separate upstream licensing/provenance. Review them before redistributing or using outputs commercially.
- Download only audio the user owns or is authorized to process. Do not add DRM, authentication, geographic, or access-control bypasses.
